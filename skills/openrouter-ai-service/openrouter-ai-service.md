# Работа с AIService и OpenRouter

Все запросы к нейросети выполняй через `AIService` из `src/services/aiService.mjs`. Не создавай отдельные `fetch`-вызовы к OpenRouter и не дублируй логику перебора моделей в composer, handler или другом сервисе.

## Модели и конфигурация

`OPENROUTER_FREE_MODELS` — канонический упорядоченный список бесплатных моделей. Его текущий порядок — приоритет:

1. `openrouter/free`
2. `inclusionai/ling-3.0-flash-fin:free`
3. `google/gemma-4-26b-a4b-it:free`
4. `google/gemma-4-31b-it:free`
5. `meta-llama/llama-3.2-3b-instruct:free`
6. `qwen/qwen3-next-80b-a3b-instruct:free`
7. `cohere/north-mini-code:free`

Не меняй порядок без явной причины: он определяет порядок fallback. Пользователь может полностью заменить список через `OPENROUTER_FREE_MODELS` — непустая строка с моделями через запятую, например:

```env
OPENROUTER_FREE_MODELS="model/a:free,model/b:free"
```

Ключ хранится только в `OPENROUTER_API_KEY`; не логируй его и не добавляй в код.

## Вызов модели

Создай или используй экземпляр `AIService` и вызывай `chatWithModelFallback`:

```js
const data = await aiService.chatWithModelFallback({
  messages: [
    { role: 'system', content: systemPrompt },
    { role: 'user', content: userPrompt },
  ],
  max_tokens: 512,
  temperature: 0.4,
  // Только когда JSON действительно нужен:
  response_format: { type: 'json_object' },
}, onStatusUpdate);

const content = data?.choices?.[0]?.message?.content?.trim() || '';
```

- Передавай `messages`, `max_tokens` и `temperature` осознанно. Если параметры не заданы, сервис использует `512` и `0.7`.
- Для структурированного результата явно задай формат JSON в промпте. `response_format: { type: 'json_object' }` используй как дополнительное ограничение, а после ответа всё равно проверяй и нормализуй JSON.
- Не предполагай, что содержимое ответа корректно: проверяй наличие `choices[0].message.content`, обрабатывай ошибки `JSON.parse`, допустимые значения полей и безопасные значения по умолчанию.
- Передавай `onStatusUpdate`, если пользователю нужно видеть переключение модели или сетевую проблему. Колбэк должен быть асинхронно безопасным и не должен раскрывать секреты.

## Правила fallback

`chatWithModelFallback` сам последовательно проходит `this.models` и возвращает первый ответ с `choices[0].message.content`.

- При `408`, `429`, `502`, `503` или `504` он переключается на следующую модель; при этих статусах сообщает о переключении через `onStatusUpdate`.
- При `429` сервис делает возрастающую небольшую задержку перед следующим запросом; не добавляй второй retry-цикл снаружи.
- Для части ответов `400` и ошибок в теле сервис также переключается, если причина похожа на rate limit, capacity/overload, unavailable или problem с model.
- Ошибка сети тоже приводит к попытке следующей модели и статусному сообщению.
- Когда все варианты исчерпаны, метод выбрасывает последнюю ошибку. Вызывающий код обязан поймать её, залогировать без секретов и вернуть своему пользователю безопасный fallback.

Не вызывай конкретную модель в обход `chatWithModelFallback`, если только задача явно не требует отказа от общего механизма. При добавлении или удалении модели обновляй только `OPENROUTER_FREE_MODELS` и сохраняй валидный OpenRouter ID.

## Добавление AI-функции

1. Сформулируй короткий, однозначный промпт и укажи нужный язык/формат ответа.
2. Вызови `chatWithModelFallback` с реалистичным лимитом токенов и низкой температурой для классификации или JSON.
3. Валидируй ответ у границы сервиса; для схемы с известной структурой используй Zod или эквивалентную строгую проверку.
4. В `catch` верни типобезопасный и нейтральный результат, чтобы сбой AI не ломал основной сценарий бота.
5. Для изменённого поведения проверь сценарии: успешный ответ, невалидный JSON, пустой `content`, `429` с переходом на следующую модель и исчерпанный список моделей.

## Нельзя

- Не используй в вызывающем коде `fetch('https://openrouter.ai/...')`.
- Не хардкодь API-ключ, модельный список или повторные попытки вне `AIService`.
- Не показывай пользователю техническое тело ошибки OpenRouter как готовый ответ.
- Не принимай торговые решения без проверок: результат AI — рекомендация, а не замена валидации рыночных данных и риск-ограничений.
